# Slidecraft · 截图制作 PPT Agent

原生 HTML / CSS / JavaScript 页面，无前端框架。上传截图后，配置的视觉模型先划分文字与图片区域；文字裁剪块交给模型完成 OCR 与 LaTeX，图片裁剪块交给模型分析几何结构，再由本地代码绘制线稿并将独立对象加入模板所选页。支持供应商 API 和本机 Codex CLI 两种接法。

## 本地启动

安装 Node.js 20.12 或更高版本，首次在项目目录执行：

```sh
pnpm install --frozen-lockfile
pnpm start
```

也可用 `npm install`、`npm start`。安装时自动复制 JSZip、Tesseract Worker、WASM 和中英文语言包到 `vendor/`。项目已包含黑板默认模板；仅在 `templates/default-template.pptx` 缺失时用演示模板初始化，已有默认模板不会被覆盖。需要重新准备资源时执行 `node scripts/setup.mjs`。

安装完成后，macOS 可双击 `start.command`（后台运行，关闭终端后仍可使用），Windows 可双击 `start.cmd`（保持终端打开）。当前 Mac 的启动脚本也会查找 Codex 自带的 Node.js。

浏览器打开 http://127.0.0.1:4173，按 Ctrl+C 结束服务。端口可通过 `PORT` 环境变量修改。不要直接打开 `index.html`，OCR Worker 需要 HTTP 服务。

需要关闭启动终端后继续使用，可执行 `pnpm start:background`。服务会在后台运行，日志与进程编号保存在 `.local/`；重复执行不会启动多个实例。电脑重启后需重新启动服务。浏览器保留页面不代表服务仍在运行。

### AI 供应商配置（可选）

不配置密钥也能运行本地中英文 OCR、图片提线、排版预览和 PPTX 导出。此时几何图使用透明 PNG，AI 精修和独立几何对象识别需要配置模型后使用。

将 `.env.example` 复制为 `.env`，填写后重启服务：

```dotenv
AI_API_KEY=你的密钥
AI_BASE_URL=https://api.siliconflow.cn/v1
AI_VISION_MODEL=Qwen/Qwen3-VL-32B-Instruct
AI_TEXT_MODEL=
```

- `AI_BASE_URL`：供应商基础地址，程序追加 `/chat/completions`。
- `AI_VISION_MODEL`：截图分区、文字/公式精修、几何图分析使用的视觉模型，需支持 `image_url` 图片输入。
- `AI_TEXT_MODEL`：中文排版要求使用的文字模型；留空沿用视觉模型。
- 原有 `SILICONFLOW_API_KEY`、`SILICONFLOW_BASE_URL`、`SILICONFLOW_VISION_MODEL` 继续兼容；非空的 `AI_*` 配置优先。迁移供应商时请同时替换地址、密钥和模型名。
- 供应商需兼容 Chat Completions 请求与 `choices[0].message.content` 响应，并能按提示词返回 JSON。不同协议的适配集中在 `ai-provider.js`；四项业务接口、提示词和校验保留在 `ai-api.js`。
- `.env` 不提交到 Git，HTTP 服务也禁止读取它。已设置的系统环境变量优先于 `.env`。线上 Worker 使用同名环境变量。

### 使用本机 Codex 登录调用 GPT

本地 Node 服务支持 `AI_PROVIDER=codex`。先确认 `codex login status` 已登录，再在 `.env` 中设置：

```dotenv
AI_PROVIDER=codex
CODEX_BIN=/本机/codex/可执行文件路径
CODEX_TIMEOUT_MS=180000
```

`CODEX_BIN` 可留空，服务会尝试 `~/.local/bin/codex`、桌面应用内置路径和 PATH。`CODEX_MODEL` 可选；`CODEX_VISION_MODEL`、`CODEX_TEXT_MODEL` 可分别覆盖，否则使用 CLI 的内置默认模型。这里不加载个人 CLI 配置，以避免启用与识别无关的工具和插件。

这是本机 CLI 调用云端 GPT，需要联网并消耗已登录 Codex 账户额度，并不是在本机部署模型。无需复制登录凭据或填写 API Key。使用官方 [非交互调用](https://developers.openai.com/codex/noninteractive) 的图片附件与结构化输出功能。

四项业务接口保持原样，`codex-provider.mjs` 负责临时图片、CLI 调用、超时和 JSON 结果解析，`ai-schemas.js` 为四项任务分别约束输出结构。使用只读沙箱，关闭 shell、应用、网页搜索与多代理功能；临时目录在请求结束后清理。失败时显示错误并保留原有本地降级处理，不自动重复消耗 Codex 额度。

恢复供应商接口只需将 `AI_PROVIDER` 改成 `api`，填入对应 `AI_*` 后重启。云端 Worker 仍使用供应商 API；Codex CLI 接法仅适用于本地 Node 服务。页面右上角显示当前配置的识别模式，该显示不代表每次模型请求都一定成功。

真实 GPT 接入时发现的题干重复与角度符号显示问题已修复：AI 段落覆盖的本地 OCR 行不会重复加入；`\angle`、`^\circ`、`^{\circ}` 会在预览和公式导出前转换为相应符号。

### 本地资源

依赖版本记录在 `package.json` 和 `pnpm-lock.yaml`，资源在安装时从包内复制，无需浏览器连接 CDN。OCR 本地路径配置参照 [Tesseract 官方说明](https://github.com/naptha/tesseract.js/blob/master/docs/local-installation.md)。

沿用仓库已有的“初中数学杨材材”水印图片和 4:3 黑板纹理 `templates/default-template.pptx`，背景图片继承自版式层。仅当默认模板缺失时用 `demo-template.pptx` 初始化；后续启动、安装和构建不会覆盖已有默认模板。`vendor/` 和 `dist/` 改为安装、构建时生成，避免提交的旧产物与源码不一致。

## 使用

1. 上传、拖放或按 Ctrl+V 粘贴 PNG / JPG / WEBP / BMP 截图（30 MB / 3000 万像素以内）。页面会在上传框下方显示读取状态和明确错误。可以先点击“试用示例”。
2. Agent 启动后自动载入 `templates` 文件夹中的默认 PPTX。选择要放入内容的模板页；其他页继续保留在导出文件中。临时模板仍可通过页面上传，只在本次页面中使用。
3. 点击“开始识别”。页面通过本地服务调用已配置的供应商 API 或 Codex CLI；密钥不会发送给浏览器。
4. 在“题干 / LaTeX”编辑器修改 OCR 文字。系统会自动把题号以外的数字、字母和数学符号放入 `$...$`；点击“自动公式化”可重新整理手动修改后的题干。`$$...$$` 表示独立公式行。编辑器下方会实时显示可读预览。
5. 每一个图片裁剪块都会单独交给视觉大模型分析。几何图先提取顶点、边、延长线、标签位置、数字标注和临时噪声；结构数据通过校验后重绘为 2400 px 透明白线图，不通过则自动回退对应原图的 4× 高清提线。校验只能证明结构可重建，仍需对照原图核对连线和数学条件。每张图片处理完成后都会在正中央单独叠加透明水印“初中数学杨材材”，文字对象不加水印。
6. 语义校验通过后，网页会显示可编辑几何画布。点击并拖动任意线条、字母或数字可改变位置；选中对象后可修改文字、颜色、线宽或字号，也可删除该对象。所有修改与 PPTX 使用同一份对象数据。
7. 每一个文字裁剪块都会单独交给大语言模型转写为可编辑文字与 LaTeX。在“个性化调整”中可直接拖动字号、文字位置、图片大小、图片位置和线条粗细；也可以输入中文要求。SiliconFlow 不可用时，本地规则仍可理解明确的字号、百分比、线宽和“保留细节 / 清晰去噪”要求。
8. 点击“生成 PPT 预览”。预览按模板页面比例和最终对象坐标绘制，同时生成 PPTX。本地 Node 服务还会将原图、预览、PPTX、识别结构及模型响应保存到 `.local/exports/` 下的独立版本目录。
9. 检查预览无误后，点击“确认无误，下载 PPTX”。在预览完成前下载按钮保持禁用；修改文字、区域、模板或图片后，必须重新生成预览。

导出的页面必须同时包含至少一个可编辑文字对象和一个图片区域，否则系统会阻止生成预览并提示补充。通过语义拓扑校验的几何图会拆成独立 PowerPoint 线条、字母文本框、数字文本框和水印对象；未通过校验的复杂图片使用独立透明 PNG 回退。模板原有内容保持。

## 排版与保留策略

- 中文为真实 PowerPoint 文本框内容：思源黑体 / Source Han Sans SC，Bold，白色。默认目标字号为 32 pt；内容较多时自动逐级缩小，个性化面板可在 8–72 pt 间指定目标字号。
- 题号保留为普通文字；其余数字、拉丁字母、希腊字母、角度与数学运算符自动写入 `$...$`，导出为同一段落内的可编辑 Office Math。公式字母使用 Cambria Math 加粗斜体，例如 `∠AOB=120°ON` 会整体公式化。独立公式行使用 `$$...$$`。支持 `\vec{}`、`\cdot`、`\times`、`\div`、`\le`、`\ge`、`\ne`、`\to` 和上标。
- 自动采用“题目在上、图片在下”的版式。题干默认从页面高度 14% 处开始，图片从 42% 处开始并按页面宽度约 72% 居中放置；图片保持原比例，不会拉伸。
- 思源黑体字体未随项目分发或嵌入 PPT。本机需自行安装，否则浏览器或 PowerPoint 会替换字体。
- 截图与模板宽高比不一致时，采用整体等比缩放并居中映射，图片不拉伸。
- 直接修改 PPTX ZIP 中所选页的 XML，追加对象及图片关系，保留原有母版、主题、背景、装饰、动画和其他页。原有模板文字也会保留，因此建议使用干净底板。
- 工作台用于检查识别区域；“PPT 预览”读取所选模板页及其版式、母版中的背景和基本元素，不再依赖整份文件的缩略图。页面显示当前底稿文件、来源和页码。组合、图表、自定义形状及部分主题效果尚不能完整还原，遇到这些元素会提示；字体和复杂效果仍以 WPS / PowerPoint 实际文件为准。

## 自动识别的边界

- OCR 使用 Tesseract.js 6.0.1；普通截图采用排除文字后的颜色连通区域检测。黑板、白板和线稿类截图会保留整幅非文字视觉内容，避免图形被拆碎或漏掉。复杂布局和细小文字仍可能误检，需要在工作台人工校正。
- 几何图裁剪时保留四周安全边距，避免靠近边缘的 A、B、C、D 等标注被截断。模型先返回可验证的“顶点—边—标注—噪声”结构；只有置信度、可见标签数量、坐标跨度、边引用、重复边和顶点连通性全部合格时才重绘。彩色填充、高亮、鼠标光标和选择标记会被过滤；验证失败自动使用原图 4× 锐化、提线与统一线宽。浅底题目会从图片上下边界恢复字母笔画，避免线稿细化把顶点标注变成不可读的小块。
- 文字字号可在 8–72 pt 间调整，纵向位置可在页面高度 0%–45% 间调整；两项继续保持独立。
- 图片大小按原始宽高比在 20%–140% 间真实缩放，图片位置按页面可用高度在 0%–100% 间真实移动；预览和导出的 PPTX 共用同一组坐标。多张图片作为带间距的整体移动，不会互相重叠。
- 多图页面优先按照截图中各图片的相对位置、尺寸和间距映射到 PPT；原图位置缺失或重叠时，自动使用整齐的网格排版。
- “清晰去噪 / 保留细节”和 1–4 pt 线宽都会重新生成 PNG；仅有固定结果的“图片输出”下拉框已移除。
- 启用模型后，图片和文字裁剪块会发给当前配置的服务。供应商 API 未覆盖配置时使用 SiliconFlow 与 `Qwen/Qwen3-VL-32B-Instruct`；本机 Codex 接法使用 `CODEX_*` 指定的模型或 CLI 默认模型。配置项见前文。
- API Key 必须保存在服务器环境变量中，不能写入前端 JavaScript、仓库或 PPTX。
- 浏览器遇到临时断网、429 或 5xx 会自动重试 3 次；登录过期会明确提示刷新并重新登录。整页视觉分析连续失败时不会终止任务，而是继续使用本地 OCR 和本地图像区域检测，避免出现“Unknown error”后识别内容为 0。
- 本地 OCR、裁剪、透明线稿和 PPTX 合成在浏览器内完成；启用大模型识别时，截图或裁剪块会经服务端发给配置的模型，API Key 不会发送到浏览器。图片模型暂时不可用时会保留安全边距，并使用本地 4× 高清去底继续生成独立图片。推荐使用近期版本的 Edge / Chrome。
- 未实现游戏计分和固定倒计时：PPT 任务展示真实识别数量、阶段进度与已用时间，模型运行时间无法准确预知。
- 当前处理一张截图到一个模板页，不支持批量截图。

## 2026-09-16：第一轮产出质量迭代

- 图内短标签按所属图形过滤，减少 A、D、C、E 等顶点字母重复进入正文；方程和题干继续保留。
- `math.js` 统一解析预览与 Office Math，处理 LaTeX 空格、分数、平方根、上下标、向量及常见符号。暂不支持的命令或不完整公式会提示校正并阻止导出；这不是完整 LaTeX 引擎。
- 识别提示词按用途区分数学刻痕与装饰性高亮，不再仅按颜色删除；当前线稿仍默认统一为白色，必须人工核对模型是否遗漏有意义的标记。
- 数字标注保留小数点、正负号、度数、根号等字符。编辑顶点关联线段时同步更新画布；删除顶点标签只删除文字，保留结构顶点与连线。重新生成预览或下载 PNG 时更新图形缓存。
- 本地每次预览成功后自动归档到 `.local/exports/<时间戳_随机ID>/`，包含 `source.*`、`preview.png`、`result.pptx`、`snapshot.json`、`metadata.json`。快照包含设置、几何对象、模型响应，元数据包含代码版本摘要与文件 SHA256。每次新建目录，不覆盖以前的产出。`EXPORT_DIR` 可覆盖存储目录，仅适用于本地 Node 服务。
- 页面提供归档 PPT 的 HTTP 下载链接。点击下载仅表示已发起下载；归档中的实际文件可直接用 WPS / PowerPoint 打开检查。

两张真实截图已在本次开发环境完成模型识别、预览、文件导出和 WPS 打开核验。原始记录缺少的文件已明确注明，未用重跑结果代替原始产出。用户的截图、模型响应及迭代导出留在本地归档，不随代码提交。

后续仍需覆盖复杂公式的跨软件显示、模板完整预览、浅底模板的文字配色、图文碰撞、多图布局、曲线及几何关系保真；目前两个样例通过不代表所有题型通过。

## 固定 PPT 模板

把常用 `.pptx` 复制到项目的 `templates` 文件夹，然后刷新网页。Agent 会列出全部内置模板，并优先自动选择文件名以 `default` 开头的模板；没有此类文件时选择按名称排序后的第一份。模板发生变化后可点击页面中的“刷新”。

项目已附带 `templates/default-template.pptx` 作为可替换示例。要永久换成自己的底板，直接用自己的文件覆盖它，文件名保持不变即可。

默认模板预览回归检查：启动本地服务后打开 `/tests/template-preview.html`，页面应显示 `PASS`。检查覆盖黑板模板的版式背景、无缩略图模板、选页独立性、占位符排除和原始模板部件保留。

## 验证

接口和本地 CLI 桥接测试：`pnpm test:api`。通过本机模拟供应商验证四项 AI 接口、自定义地址、视觉/文字模型分流和旧配置兼容，不调用真实付费模型。

浏览器测试：准备 Playwright 和 Chrome 后运行 `pnpm test`；Playwright 不在项目内时，设置 `PLAYWRIGHT_PATH` 为已安装包的绝对路径。用 `BROWSER_CHANNEL` 切换浏览器通道。

测试自动在本机 4175 端口启动独立服务（可用 `TEST_PORT` 修改），验证本地资源、真实示例 OCR、透明线稿、文字和 Office Math 导出、模板原有部件保留、预览失效和重置。浏览器测试阻断外部请求，并使用空密钥，保证覆盖本地降级流程。临时输出自动清理；设置 `TEST_OUTPUT_DIR` 可保留生成的 PPTX 和预览截图。

真实 Codex 测试（会消耗账户额度）：准备 Playwright 与 Chrome 后显式运行 `pnpm test:codex`。测试生成带中文题干的三角形图片，调用四个真实接口，检查可编辑几何线、字母、公式及 PPTX 导出，结果保存到 `../outputs`（可用 `TEST_OUTPUT_DIR` 修改）。常规 `pnpm test` 不会调用真实模型。

`pnpm build` 生成 `dist/client` 和 `dist/server`。如有 `.openai/hosting.json` 会复制部署配置；缺少该配置时仍可生成产物，但不代表已配置或发布线上站点。
